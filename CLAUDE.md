# rockawayevents.org — Rockaway Events hub

**Owner:** Jamal Khan (jkhan626). **Purpose:** the one public page for everything happening on the Rockaway peninsula (Queens, NYC): events feed + calendar, weekly recurring activities (run clubs, markets, surf, yoga, trivia), beach conditions, and a public "submit an event" form. No sign-in for visitors. Zero running cost beyond the domain (Netlify free-tier features only, free public APIs, Notion as the CMS).

Modeled on jamasha.com/events (`../Wedding/`): static `dist/` + Netlify Functions reading Notion server-side. Same NOTION_TOKEN integration.

## Data model (Notion)
Two Notion databases feed the site, both read by `netlify/functions/events.js`:

1. **New public DB — "🏖️ Rockaway Events (rockawayevents.org)"**
   - database id `c83a031ec6644f04a21800790660c9d4`, data source `8fa65a7c-22c4-435c-9b85-968a7997407e`, child of the "Events & Happenings" page `367d0214-3872-81da-bdd6-c5d82ae80ecc` (so the NOTION_TOKEN integration inherits access).
   - Properties: `Event` (title), `Date` (date), `End Date` (date), `Time` (rich_text, human readable), `Venue` (rich_text), `Address` (rich_text), `Category` (multi_select: Music, Food & Drink, Run & Fitness, Surf & Beach, Kids & Family, Arts & Culture, Community, Market, Nightlife, Volunteer, Outdoors, Sports, Other), `Cost` (rich_text), `Free` (checkbox), `URL` (url), `Instagram` (url), `Image` (url), `Description` (rich_text), `Status` (select: Approved / Pending / Rejected), `Source` (select: Community, Instagram, Rockaway Times, NYC Parks, Web, Jamal, Routine), `Recurring` (select: None / Weekly / Monthly), `Days` (multi_select Mon..Sun), `Featured` (checkbox), `Submitter Name` (rich_text), `Submitter Email` (email), `Submitted` (created_time).
   - Only `Status = Approved` rows are public. Community submissions are created as `Pending`.
   - **Recurring rows:** `Recurring = Weekly` + `Days` = which weekdays; `Date` = first date it applies from (optional), `End Date` = when the series ends (optional). `Monthly` = same weekday-of-month pattern as `Date` (e.g. "2nd Saturday"). The events function expands these into concrete occurrences for the next 60 days.

2. **Legacy NYC-wide DB — "🎟️ Events & Happenings"** `bf66333b0ca142ffb28233fdb5774e64` (populated daily at 3:10 AM ET by the cloud routine in `../Claude Agent/agents/events-and-happenings.md`). Read it filtered to `Neighborhood = Rockaway` and `Status != Skip`. Its schema: `Event` title, `Date`, `End Date`, `Time`, `Venue`, `Neighborhood` select, `Type` multi_select, `Distance (mi)` number, `Cost` rich_text, `Source` select, `URL` url, `Description` rich_text, `Status` select. Strip a leading `⭐ ` from titles. Map `Type` names into our `Category` list best-effort (else `Other`), set `source: "Routine"`. Reference implementation of the Notion query + dedup: `../Wedding/netlify/functions/events.js`.

## API contract (all under `/api/*`, wired in `netlify.toml`)
- `GET /api/events` -> `{ updated, today, count, events: Event[] }` sorted by date then start time. Merges both DBs, expands recurring rows, dedups near-duplicates (same date + fuzzy title key, like jamasha's `dedupEvents`). Cache: `public, max-age=300` + `Netlify-CDN-Cache-Control: public, max-age=600, stale-while-revalidate=3600`.
  - `Event = { id, seriesId?, event, date:"YYYY-MM-DD", dateEnd:null|"YYYY-MM-DD", time:string, timeStart:null|"HH:MM", venue, address, category:string[], cost, free:boolean, url, instagram, image, description, source, featured:boolean, recurring:"None"|"Weekly"|"Monthly", days:string[] }`
  - Recurring occurrence ids are `<pageId>_<YYYY-MM-DD>`; `seriesId` = page id.
  - Window: today (America/New_York) through today + 60 days; multi-day events stay while `dateEnd >= today`.
- `GET /api/enrich-images?key=<MODERATE_KEY>` -> fills the `Image` column of both DBs from each event page's og:image. Also runs nightly on a Netlify schedule at 4:20 AM ET (`[functions."enrich-images"]`, `20 8 * * *`), 70 minutes after the 3:10 AM routine. Never touches Instagram: those URLs expire. Full write-up in `README-backend.md`.
- `GET /api/conditions` -> beach conditions for Rockaway Beach (approx 40.5834, -73.8155). Free, keyless sources, each failing independently: NWS `api.weather.gov` (needs a `User-Agent` header), Open-Meteo forecast + marine APIs, NOAA CO-OPS tide predictions (nearest tide-prediction station to Rockaway Beach; verify the station id against the NOAA station metadata API rather than guessing), NDBC buoy 44065 water temp. Shape: `{ updated, now:{tempF, feelsF, windMph, windDir, uv, skies, precipChance}, water:{tempF, waveFt, wavePeriodS, waveDir}, tides:[{type:"H"|"L", time(ISO), heightFt}] (next 4), sun:{rise, set}, forecast:[{date, day, hi, lo, precip, short}] (5 days), beachScore:{score:0-10, label, reasons:string[]}, lifeguards:{onDuty:boolean, season:string, hours:string} }`. NYC beach season: Memorial Day weekend through mid-September, lifeguards 10 AM to 6 PM. Cache 15 min.
- `GET /api/calendar.ics` -> iCalendar feed of all events (`X-WR-CALNAME: Rockaway Events`, `Content-Type: text/calendar`), so people can subscribe in Google/Apple Calendar. Cache 1h.
- `GET /api/feed.xml` -> RSS 2.0 of upcoming events. Cache 1h.
- `GET /api/ferry` -> NYC Ferry Rockaway departures (copy of jamasha's `lib/ferry-core.js` + wrapper).
- **Submissions:** Netlify Forms (free, spam-filtered, no SMTP needed). The static form on `dist/submit/index.html` is `name="event-submit"` with `data-netlify="true"` + honeypot `netlify-honeypot="bot-field"`. The function `netlify/functions/submission-created.js` (Netlify calls this name automatically on every form submission) creates a `Pending` row in the new DB via the Notion REST API. Fields: `event, date, endDate, time, venue, address, category (multi), cost, free, url, instagram, image, description, recurring, days (multi), name, email`. Success redirects to `dist/submit/thanks.html`.
- **Moderation:** `GET /api/pending?key=` lists Pending rows; `POST /api/moderate` `{ id, action:"approve"|"reject", key }` flips Status. `key` must equal env `MODERATE_KEY`. Admin page `dist/admin/index.html` (noindex) asks for the key once (sessionStorage), lists pending cards with Approve/Reject buttons. Jamal can also just edit Status in Notion.

## Frontend (`dist/index.html`, single file, mobile-first)
**Look and feel: Jamal's reference is clyx.com/feed, "but in a calendar style".** That means: a grid of tall poster-style event cards (on a LIGHT sand background, see Design) (image-first, 2 columns on phone, 3 to 4 on desktop), each card with the event image or flyer on top, a small calendar-tile date badge (month over day number), an uppercase title, time, venue line, and category pills. Top bar: wordmark "Rockaway Events", search, and a horizontally scrollable day strip (Today, Tomorrow, then dates) that filters the grid; plus a full month calendar view (toggle) where each day shows dots/counts and tapping a day filters the feed. **Every card carries a photograph.** `imageFor()` in `dist/index.html` picks, in order: the event's own `image` (filled in nightly by `enrich-images.js`), then a `VENUE_IMAGES` match on venue plus address, then the photo for the event's first `Category`, then `rockaway.jpg`. The pictures live in `dist/img/fallback/` (20 Unsplash photos, ~1.6 MB, credited in `dist/img/fallback/CREDITS.md`, rebuilt by `scripts/fetch-fallback-photos.js`). **None of them is a photograph of a real Rockaway venue** and none is ever captioned as one: where a venue has no freely licensed photo, which is all of them, it maps to a mood match instead. The card title sits on the photo over a dark bottom scrim, with the date tile beneath it, so an og:image card and a fallback card read identically. The generated category gradient survives only as the `onerror` net when a photo fails to load.

Instagram post photos are not hotlinked. The daily Instagram scan saves them with `scripts/save-ig-image.js` into `dist/img/ig/<postcode>.jpg` and puts that URL in the Notion `Image` column. Secondary reference is secretnyc.co (editorial, big images).

Page sections in order: top bar; beach conditions strip (compact: air temp, water temp, waves, next tide, UV, a "beach score" out of 10, lifeguard status; from `/api/conditions`); day strip + filter chips (All / Free / category chips) + List/Calendar toggle; the feed grid (grouped by day headers in list mode; featured events pinned first within their day); **Every week** section (recurring series grouped by weekday, compact rows); a "Submit an event" CTA card; footer (subscribe-to-calendar `webcal://` link, RSS, email hello@rockawayevents.org, about, Instagram). Tapping a card opens a detail sheet/modal: full description, address with Google Maps link, Info/Tickets link, Instagram link, Add to Calendar (Google Calendar URL + per-event .ics via data URI), Share (Web Share API with clipboard fallback), and a deep link (`#e=<id>`). Search-engine friendly: full meta/OG tags, `schema.org/Event` JSON-LD injected after fetch, indexable (this site WANTS Google traffic, unlike jamasha). `manifest.webmanifest` + SVG icon so Add to Home Screen works.

## Design (LIGHT theme, Jamal's call 2026-09-12; overrides the earlier dark spec)
Light "sand and ocean" palette, readable in sunlight on a phone: page background sand `#FBF6EC`, cards white `#FFFFFF` with a 1px `#E6DCC8` border, elevated/section background `#F3EAD8`, text ink `#16242F`, muted `#5C6670`, ocean accent `#1F6F8B` (links, active chips, calendar dots), lifeguard orange `#E2572B` for the primary CTA and the date-tile badge, sea-glass `#2E8B6E` on a pale `#DDF1E8` for Free badges, sand-gold `#C9A96E` for the Featured locals accent. Generated posters for image-less events use soft category-tinted gradients (pastel, not neon) with ink text. Keep the Clyx-style poster grid and layout unchanged, just in light colors. Optional dark mode via `prefers-color-scheme: dark` is fine but the default must be light. Fonts: Plus Jakarta Sans 600-800 (display/titles; Jamal rejected Fraunces on 2026-09-12 because of its hooked J) + Inter (body) from Google Fonts. Plain and fast: 1px borders, no scroll animations, no marquee, no hype. **Copy rules:** no em dashes, no emojis in copy, plain sentences.

## Email (Resend) and newsletter
- Transactional email goes through **Resend** (REST, no SDK) via `netlify/functions/lib/email.js`: Jamal gets a "New event submitted" email (with admin + Notion links), submitters get a confirmation, and an "Your event is live" email on approve. `POST /api/subscribe` adds a contact to a Resend Audience (footer "weekly Rockaway rundown" box). All of it no-ops cleanly until the env vars exist.
- **Env vars:** `RESEND_API_KEY` (required; `RESEND_AUDIENCE_ID` is optional, only for older Resend accounts with multiple audiences; Jamal's account uses the single account-wide audience so POST /contacts is used) (set 2026-09-12; domain rockawayevents.org verified in Resend, DKIM + send/rsend CNAMEs + DMARC at Namecheap), `NOTIFY_EMAIL` (set: jamalknyc@gmail.com), `EMAIL_FROM` (set: `Rockaway Events <hello@rockawayevents.org>`).
- Sending from hello@rockawayevents.org via Resend needs the domain verified in Resend: DKIM TXT `resend._domainkey`, plus MX + SPF TXT on the `send` subdomain (values come from the Resend dashboard). These do not conflict with Namecheap's inbound forwarding MX on the apex.
- Netlify Forms also emails jamalknyc@gmail.com on every submission (site hook `submission_created`), so submissions are never missed even without Resend.
- Weekly newsletter plan: Resend Broadcasts to the audience (free tier: 3,000 emails/mo, 1,000 contacts). A Claude routine can draft "This week in Rockaway" from `/api/events`.

## Card images (added 2026-09-12 at Jamal's request)
Three layers, in priority order: (1) `Image` property on the Notion row; filled automatically by the scheduled function `enrich-images` (daily 4:20 AM ET, or `GET /api/enrich-images?key=<MODERATE_KEY>`) which reads each event's `URL` and stores its og:image (both DBs now have an `Image` url property; a sentinel `https://rockawayevents.org/img/none` marks "checked, nothing found"). (2) Instagram post photos: the local `rockaway-ig-event-scan` task downloads the post image, runs `node scripts/save-ig-image.js <file> <postcode>` to write `dist/img/ig/<postcode>.jpg`, sets `Image` to the public URL, then commits + deploys. Instagram CDN URLs are never stored (they expire; `events-core.js` nulls any cdninstagram/fbcdn URL). (3) Frontend fallbacks in `dist/index.html`: venue photo match (`VENUE_IMAGES`) -> category photo (`dist/img/fallback/`) -> generic Rockaway shot; the generated gradient poster is only the `onerror` fallback. Credits in `dist/img/fallback/CREDITS.md`.
